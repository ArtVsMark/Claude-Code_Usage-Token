# claude-code-usage

**Сколько на самом деле осталось от лимитов Claude Code — в цифрах, а не в светофоре.**

> 🇬🇧 [English version](README.en.md) · Неофициальный инструмент, к Anthropic отношения не имеет.

## Проблема

Claude Code показывает состояние лимитов тремя ступенями:

```
allowed  →  allowed_warning  →  rejected
```

Планировать по такому нельзя. «Warning» означает и половину запаса, и последние
проценты — а узнать, сколько именно осталось, неоткуда: ни числа, ни доли в
доступных интерфейсах нет.

Практическое следствие знакомо каждому, кто гоняет агентские окна: браться за
большую задачу или подождать сброса — решается наугад.

## Идея

Остаток не запрашивается, а **измеряется**.

Рядом со светофором лежит фактический расход каждой сессии — прочитанный кэш,
выданные токены, условная стоимость. Инструмент снимает эти замеры, копит их и
считает потребление за окно: пятичасовое и семидневное.

Дальше он **калибрует сам себя**: запоминает, какому суммарному расходу
соответствовало переключение `allowed → warning`, потом `warning → rejected`.
Через две-три недели набирается собственная шкала — и остаток начинает
считаться в процентах, без всякого доступа к внутренним лимитам.

## Как устроено хранилище

Без сервера и без базы данных. Замеры дописываются строками **JSONL** в git —
в приватный репозиторий рядом.

Причина архитектурная: замер может сделать только окно (данные живут в реестре
сессий), а облачное окно эфемерно — его файловая система исчезает вместе с
контейнером. Значит хранилище обязано быть внешним, и git подходит лучше
сервера: он распределённый, версионированный и доступен из любого окна.
Append-only строки сливаются без конфликтов, даже когда пишут несколько окон
разом.

Сервер добавил бы к этому только точку отказа.

откалибрована». Это заложенное поведение, а не недоделка.
