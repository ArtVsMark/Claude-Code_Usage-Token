# Хранилище: подготовка перед первым замером

Инструмент ничего не хранит у себя. Первая же команда `sample` пишет в
**приватный репозиторий**, и если он не подготовлен, отказ будет не сразу и не
внятный: строки начнут конфликтовать при слиянии через несколько замеров, а не
при первом.

Поэтому подготовка — отдельный шаг, а не часть первого запуска.

## Что должно быть готово

| Что | Значение |
|---|---|
| приватный репозиторий | у мейнтейнера — [`Claude-Code_Usage-Data`](https://github.com/ArtVsMark/Claude-Code_Usage-Data); у стороннего человека — свой |
| файл `samples/usage.jsonl` | может быть пустым, но должен существовать и быть закоммичен |
| `.gitattributes` со строкой слияния | без неё замеры из двух окон дадут конфликт |
| право записи из **обоих** окон | локального и облачного |
| путь в конфиге | не в коде — см. ниже |

Репозиторий **приватный, и это не рекомендация.** Ряд замеров за месяц — это
распорядок дня и условная стоимость работы; см. [`SECURITY.md`](../SECURITY.md).

## `.gitattributes`

В корне хранилища:

```
samples/usage.jsonl merge=union
```

`merge=union` означает: при слиянии git берёт строки **обеих** сторон вместо
того, чтобы объявить конфликт. Для append-only файла это ровно нужное
поведение — два окна, писавшие одновременно, дают файл с обеими строками.

Отсюда два следствия, обязательных для всякого, кто читает или пишет файл:

- **строки не редактируются и не удаляются.** Исправление — это новая строка.
  Правка задним числом ломает предсказуемость слияния: `union` не сверяет
  содержимое, он объединяет;
- **порядок строк не гарантирован.** Слияние объединяет, но не сортирует.
  Упорядочивать по `ts` обязан **читатель**, и полагаться на порядок в файле
  нельзя даже тогда, когда он выглядит правильным.

Второе следствие — самое лёгкое место для ошибки: на одном окне файл почти
всегда упорядочен, и код, читающий его подряд, будет годами работать, пока не
появится второе окно.

## Путь к хранилищу — из конфига

Путь задаётся **конфигом или переменной окружения**, не константой в коде.
Причина не в красоте: посторонний человек должен поставить инструмент и
направить его в своё хранилище, ничего не правя в исходниках. Хранилище
мейнтейнера ему недоступно, и захардкоженный путь превращает инструмент в
личный скрипт.

Переменная называется **`CLAUDE_CODE_USAGE_STORE`**, и её перебивает флаг
`--store`. Файла конфигурации нет: третий источник истины пришлось бы держать в
согласии с двумя первыми, а надобности в нём пока не возникло. Появится случай,
когда переменной не хватает, — появится и конфиг, вместе с этим случаем.

Готовность хранилища `sample` проверяет **до первой записи** и называет всё
несделанное разом: не git-репозиторий, нет `samples/usage.jsonl`, нет строки
`merge=union`. Именно потому, что последняя отказывает не при первом запуске, а
через несколько замеров.

## Как проверить, что подготовлено верно

Проверка ровно одна, и она про слияние, потому что остальное отказывает громко:

1. Из первого окна дописать строку в `samples/usage.jsonl` и запушить.
2. Из второго окна, **не подтягивая** первое изменение, дописать свою строку и
   запушить.
3. Слить. Ожидаемо: в файле обе строки, конфликта нет.

Если на третьем шаге git показал конфликт — `.gitattributes` не подхватился.
Частая причина: файл добавлен, но не закоммичен, либо строка описывает не тот
путь.

## Чего в хранилище не бывает

Ни токенов, ни ключей, ни содержимого сессий, ни названий задач — только расход
и состояние лимита, по белому списку полей. Проверяется **до** коммита, а не
после: приватный репозиторий уменьшает ущерб от утечки, но не отменяет её.

## Открытый вопрос

Как облачное окно получает право записи в приватное хранилище — не решено.
Локальное окно пишет под учётной записью человека; у облачного этих прав нет по
умолчанию, а выдавать ему постоянный токен — заводить секрет, который придётся
где-то хранить.

Вопрос разбирается в
[#2](https://github.com/ArtVsMark/Claude-Code_Usage-Token/issues/2) вместе с самой
командой. До его решения замеры копятся только из локального окна — и это
отдельная причина не доверять ранней шкале: она построена по неполной сумме, о
чём говорит [#13](https://github.com/ArtVsMark/Claude-Code_Usage-Token/issues/13).
