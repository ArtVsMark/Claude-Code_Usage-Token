# Роли

В [`CLAUDE.md`](../CLAUDE.md) роли объявлены таблицей. Таблица отвечает на
вопрос «кто за что отвечает» — и не отвечает ни на один из тех, которые
возникают в работе: **когда роль включается, что она проверяет и что имеет
право остановить.**

Без этого роль остаётся украшением. Здесь она описана так, чтобы её можно было
исполнить.

## Как это читать

Роль — **точка зрения, а не человек**. Людей в агентском окне нет, и делить
обязанности не между кем: одно окно проходит все роли по очереди.

Отсюда единственное практическое требование: **смена роли должна быть
заметной**. «Я посмотрел на это со всех сторон» — не смена роли, а
самоуспокоение. Роль включается тогда, когда наступило её событие, и задаёт
ровно свой вопрос, даже если ответ заранее кажется очевидным.

Порядок по ходу задачи:

```
🏛 Архитектор  →  📐 Метролог  →  🔧 Разработчик + 🧪 Тестировщик
                                          ↓
📦 Релиз-инженер  ←  🧠 Методист  ←  🔐 Хранитель данных
```

Архитектор первым: он решает, делается ли задача вообще. Хранитель данных
предпоследним: он смотрит на готовый дифф, а не на замысел.

---

## 📐 Метролог

> «На чём основана эта цифра и какова её погрешность?»

**Главная роль проекта.** Инструмент, который показывает неверную цифру
уверенным тоном, хуже отсутствующего: по нему принимают решения.

| | |
|---|---|
| **Включается** | как только в выводе, в тесте или в документе появляется число |
| **Проверяет** | названо ли, из чего число получено; отделена ли оценка от факта; названа ли погрешность — сколько замеров легло в оценку, когда был последний, сколько калибровочных точек |
| **Блокирует** | процент остатка при пустой шкале; «примерно», «около», «≈» без указания источника; округление, скрывающее разброс; счёт по окну, объявленному закрытым сразу после последнего замера |
| **Не его дело** | быстродействие, устройство хранилища, формулировки витрины |

Практический признак: если цифру нельзя сопроводить фразой «получена из
стольких-то замеров, последний тогда-то» — она не готова к выводу.

## 🔐 Хранитель данных

> «Что из этого нельзя показывать никому?»

| | |
|---|---|
| **Включается** | перед каждым коммитом и перед каждой записью в хранилище |
| **Проверяет** | что поля замера прошли по **белому** списку; что нет ключей, токенов, содержимого сессий и названий задач; что путь к хранилищу берётся из конфига, а не из кода; что в этом репозитории нет ни одного файла замеров |
| **Блокирует** | чёрный список вместо белого; «обезличенный» файл замеров в PR; поле, добавленное «на всякий случай»; секрет в примере из документации |
| **Не его дело** | точность шкалы, удобство формата |

**Вето безусловное.** Остальные роли спорят и уступают, эта — нет: утечку
нельзя откатить. Публичный git помнит удалённое, а замеры — это картина чужой
активности по часам, а не тестовые данные.

Белый список, а не чёрный, — по той же причине: чёрный не переживёт добавления
нового поля в реестр сессий. Новое поле должно **не попасть** в замер по
умолчанию, а не попасть в него до первой правки списка.

## 🏛 Архитектор

> «Не переоткрываем ли мы решённое?»

| | |
|---|---|
| **Включается** | когда предложение касается хранилища, источника данных или границ проекта |
| **Проверяет** | три инварианта из [`CLAUDE.md`](../CLAUDE.md); не появилась ли зависимость от соседнего проекта; не пришёл ли механизм раньше своей причины |
| **Блокирует** | сервер, базу данных, замер из workflow, попытку запросить лимит у API — до обсуждения в issue |
| **Не его дело** | как именно написан код, проходящий по инвариантам |

Инварианты обсуждены и приняты; предложение, нарушающее любой из них,
обсуждается в issue **до** написания кода, а не в PR. Это не запрет на
пересмотр — это требование пересматривать до того, как написан код, который
жалко выбросить.

## 🔧 Разработчик

> «Работает ли это в обоих окнах — локальном и облачном?»

| | |
|---|---|
| **Включается** | при написании кода |
| **Проверяет** | пути, кодировки и поведение файловой системы на Windows и Linux; что облачное окно эфемерно и ничего не хранит между запусками; что повторный запуск не портит файл |
| **Блокирует** | код, тронувший файловую систему и проверенный только там, где удобно |
| **Не его дело** | решать, нужна ли задача |

Оба окна — не абстракция: облачное окно ходит на Linux, локальное на Windows,
и слепая зона получается ровно в том из них, где инструментом пользуются
руками.

---

## 🧪 Тестировщик

> «Как это падает, если реестр вернул мусор?»

| | |
|---|---|
| **Включается** | вместе с кодом, а не после него |
| **Проверяет** | поведение на подделанных данных: мусор вместо JSON, оборванная строка, пустой ответ, незнакомый статус светофора, недоступный реестр |
| **Блокирует** | молчаливую пустую строку вместо отказа; тест, покрывающий только счастливый путь; профильную выборку вместо всего набора |
| **Не его дело** | красота кода |

Требование к отказу: **громкий**. Ненулевой код возврата и сообщение, которое
называет, что именно не вышло. Замер, тихо записавшийся пустым, отравляет
шкалу — и обнаружится через недели, когда исправлять уже нечего.

## 🧠 Методист

> «Поймёт ли это человек, пришедший со стороны?»

| | |
|---|---|
| **Включается** | при правке любого документа |
| **Проверяет** | что `README.md` и `README.en.md` не разошлись по смыслу; что новое правило записано в [claude-code-playbook](https://github.com/ArtVsMark/claude-code-playbook) тем же заходом; что термин не введён во второй раз другими словами |
| **Блокирует** | расхождение витрин; правило без причины; пересказ issue вместо ссылки на неё |
| **Не его дело** | техническая верность утверждения — это к Метрологу и Архитектору |

Расхождение витрин — **ошибка перевода, а не два разных утверждения**. Русская
витрина источник истины; если верна английская, правится русская, и обе едут
одним коммитом.

## 📦 Релиз-инженер

> «Что увидит тот, кто поставит пакет?»

| | |
|---|---|
| **Включается** | при выпуске версии |
| **Проверяет** | что запись в changelog добавлена фрагментом вместе с изменением, а не написана по памяти после; что витрина пакета читается у того, кто пришёл без контекста |
| **Блокирует** | выпуск с недостоверным описанием возможностей |
| **Не его дело** | содержание самих изменений |

**Роль пока спит:** проект не выпускался ни разу, формат changelog заведём при
первом релизе. Записано здесь, чтобы при выпуске не изобретать заново.

## Когда роли спорят

Три столкновения, которые в этом проекте неизбежны. Разрешаются они не
голосованием, а заранее назначенным старшинством.

**🔐 Хранитель данных ↔ 📐 Метролог.** Точность хочет больше полей в замере,
приватность — меньше. **Сильнее Хранитель.** Недостающая точность — это
неточность, названная вслух; утечка не отменяется ничем.

**🏛 Архитектор ↔ 🔧 Разработчик.** «Дешевле сделать вот так» против
инварианта. **Сильнее Архитектор** — но не молча: возражение уходит в issue.
Инвариант, который нельзя обсудить, через полгода снимут как избыточный.

**📐 Метролог ↔ 📦 Релиз-инженер.** Выпускать ли версию с неоткалиброванной
шкалой. **Выпускать можно, врать нельзя:** «шкала не откалибрована, остаток
неизвестен» — правильное поведение инструмента, а не недоделка.

## Чего в этом документе нет

Назначений, расписания и процедуры согласования. Роль здесь — обязанность
задать вопрос в нужный момент, и ничего больше. Механизма, который бы это
проверял, тоже нет: гейты и конвейер живут в эпике
[#3](https://github.com/ArtVsMark/claude-code-usage/issues/3).

Пока механизма нет, документ действует как **намерение**. Написан он потому,
что намерение, записанное до первого инцидента, ещё можно обсудить, а
восстановленное после — уже нет.
