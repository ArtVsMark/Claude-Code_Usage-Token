# Записи changelog — фрагментами

Одна запись — **один файл**, и он едет вместе с изменением, а не дописывается в
общий документ задним числом.

## Почему так

**Конфликты.** Правка одного `CHANGELOG.md` всеми ветками подряд даёт конфликт
на каждом втором PR — причём в месте, которое сливать бессмысленно: строки
независимы, а git об этом не знает.

**Правдивость.** Запись, написанная после релиза, пишется по памяти и врёт.
Запись, приезжающая вместе с изменением, описывает то, что автор только что
сделал и ещё помнит.

## Формат

```
changelog.d/<что-изменилось>.<вид>.md
```

Имя называет, **что изменилось**: латиница, цифры, дефис —
`pr-template-not-a-link.fixed.md`. Номер задачи идёт **последней строкой**
записи:

```markdown
Гейт разметки PR больше не пропускает нетронутый шаблон.

#151
```

**Номером файл не называют, и это замер.** Прежде имя было `<номер задачи>.<вид>.md`,
и все изменения по одной задаче писали в один файл: за одну серию порции по
#151 дали три конфликта слияния подряд, а запись выросла до пяти несвязанных
строк. Имя по смыслу не сталкивается никогда. Имя из одного номера —
отказ. Схема та же, что у конвейера механизмов, на который проект переезжает
(#158).

| Вид | Раздел |
|---|---|
| `added` | Добавлено |
| `changed` | Изменено |
| `fixed` | Исправлено |
| `removed` | Убрано |
| `internal` | Внутреннее |

Список закрытый. Запись неизвестного вида потерялась бы при сборке молча,
поэтому вид вне списка — отказ.

**`internal` — ответ «тому, кто ставит пакет, не нужно», и он называет
причину.** Первой строкой записи идёт ровно она:

```markdown
> **Потребителю безразлично:** <почему это его не касается>
```

Без причины «не нужно» неотличимо от «забыли» (правило 154 каталога).

Содержимое — одна-три строки **по-русски**: `CHANGELOG.md` и release notes
публикуются наружу и пишутся на языке проекта.

## Запись из одних идентификаторов

Бывает законной: «`ruff` поднят до 0.6» не содержит ни одной русской буквы по
природе. Такая запись объявляет себя **строкой-маркером**, а не угадывается:

```markdown
<!-- только идентификаторы -->
`ruff` поднят до 0.6
```

Механизм явный намеренно. Эвристика «нет кириллицы — значит не переведено»
краснела бы на верной записи, а эвристика по длине не говорит ни о чём: короткая
русская запись законна, длинная английская — нет.

## Кому запись нужна

PR с типом `bug` или `enhancement` — то есть меняющий поведение. Правка
документов (`documentation`) записи не требует: требовать её значило бы разводить
шум, в котором потеряется настоящая запись.

## Строгость по месту

| Где | Язык записи |
|---|---|
| на PR | предупреждение — запись ещё правится |
| при релизе | **отказ** — публикация необратима |

Держит это `scripts/changelog.py`, прогон
[`.github/workflows/changelog.yml`](../.github/workflows/changelog.yml).

## Куда они деваются

При подготовке версии фрагменты **складываются в свод** и удаляются:

```
python scripts/changelog.py --fold --strict --version vX.Y.Z
```

Раздел уезжает в [`CHANGELOG.md`](../CHANGELOG.md), а заметки выпуска берутся
уже оттуда. Пока фрагменты оставались на месте, заметки следующего выпуска
повторили бы записи прошлого целиком.

Пустой каталог — законное состояние: он пуст ровно с момента подготовки версии
до первого изменения после неё.
